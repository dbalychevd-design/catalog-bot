# Catalog Studio Bot

Приватный Telegram-бот для создания **бренд-профилей (Custom Service)** и товарных карточек. Данные хранятся в SQLite, поэтому не исчезают при обычном перезапуске процесса, если файл базы находится на постоянном диске.

## Что реализовано

Бот поддерживает приватный доступ через заявки. Владелец получает заявку в Telegram и может принять или отклонить пользователя. После одобрения пользователь получает роль **Создатель**, а его профили и объявления изолированы от данных других пользователей.

| Роль | Возможности |
|---|---|
| Владелец / админ | Принимает заявки, меняет роли, видит статистику проекта |
| Создатель | Создаёт и управляет только собственными профилями и объявлениями |
| Наблюдатель | Открывает свои разделы без создания нового контента |

Сценарий Custom Service: название → логотип (или пропуск) → красный/свой/отложенный стиль → favicon (или пропуск) → предпросмотр.

Сценарий объявления: профиль → название → цена → данные доставки → фото → предпросмотр → черновик или готово к публикации.

> В поле доставки следует указывать только публичные условия продавца: город отправки, адрес магазина или условия доставки. Не собирайте адреса или другие данные покупателей через этот бот.

## Локальный запуск (по желанию)

Для запуска на своём компьютере нужен Python 3.11 или новее. Создайте файл `.env` рядом с `.env.example`, скопируйте в него значения из примера и заполните только новый токен бота и свой Telegram ID.

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
python app.py
```

После запуска отправьте боту `/start`. Пользователь с ID из `ADMIN_ID` автоматически становится Владельцем.

## Публикация через GitHub и Render

Сначала создайте **приватный** GitHub-репозиторий. Загрузите в него содержимое этой папки, но не добавляйте файл `.env` и папку `data/` — `.gitignore` уже защищает их от случайной загрузки.

В панели Render создайте новый **Web Service**, подключите GitHub-репозиторий и укажите следующие команды:

```text
Build Command: pip install -r requirements.txt
Start Command: python app.py
Health Check Path: /health
```

В разделе Environment добавьте переменные `BOT_TOKEN`, `ADMIN_ID`, `DATABASE_PATH`, `PROJECT_TITLE`, `PROJECT_DESCRIPTION`, `DEFAULT_CURRENCY`, `SUPPORT_USERNAME`, `COMMUNITY_URL` и при наличии `PROJECT_IMAGE_FILE_ID`.

Для базы на постоянном диске добавьте диск Render и подключите его по пути `/var/data`. После этого установите:

```text
DATABASE_PATH=/var/data/catalog.db
```

Без постоянного диска Render может удалить SQLite-файл при перезапуске или новом деплое. Постоянный диск сохраняет только данные в своей папке и доступен одному экземпляру сервиса. [1]

## Перенос на VPS позже

На VPS скопируйте папку проекта и SQLite-базу `catalog.db`, затем укажите в `.env` путь, например:

```text
DATABASE_PATH=/opt/catalog-studio/data/catalog.db
```

После переноса создайте резервную копию базы перед обновлениями:

```bash
cp /opt/catalog-studio/data/catalog.db /opt/catalog-studio/backups/catalog-$(date +%F).db
```

## Безопасность

Никогда не добавляйте токен Telegram-бота в Python-файлы, GitHub, Pastebin или переписку. Если токен уже публиковался, отзовите его через BotFather и создайте новый **до первого запуска этого проекта**.

[1]: https://render.com/docs/disks "Render — Persistent Disks"


## Шаблоны данных отправки

На шаге `Создание карточки · 3/4` Создатель выбирает ранее сохранённый шаблон или создаёт новый. Шаблон содержит только публичные данные продавца или места отправки: название шаблона, город, ZIP-код, имя и фамилию контактного лица, улицу и номер дома. Один Создатель может хранить несколько вариантов, например `Основной` и `Магазин · Bern`.

Выбранный шаблон сохраняется вместе с объявлением. Если добавить новую карточку позже, сохранённые шаблоны снова появятся в inline-кнопках. Адреса и другие персональные данные покупателей через этот сценарий не собираются.

После выбора шаблона шаг `4/4` предлагает фотографию товара или кнопку `Без фото`. Оба варианта ведут к предпросмотру карточки.

## Обновление существующей SQLite-базы

При запуске бот автоматически создаёт таблицу `shipping_templates`. Если в старой таблице `listings` ещё нет поля связи с шаблоном, приложение добавляет его при инициализации. Существующие профили и объявления не удаляются.

После обновления остановите бота, замените файлы проекта, сохранив свой `.env` и папку `data/`, затем снова запустите `python app.py`.

## Следующий этап

После проверки карточек можно добавить публичный идентификатор объявления и безопасную ссылку на лендинг. Лендинг будет получать конфигурацию конкретной карточки: профиль Custom Service, логотип, тему, название, фото, цену, валюту и публичные данные отправки. Telegram-токен не должен находиться в HTML или JavaScript лендинга; события открытия страницы будут проходить через backend.

Сценарии платёжных карт, CVV/CVC и OTP/OTRC не реализуются в самописном лендинге. Для оплаты в будущем следует использовать официальный checkout платёжного провайдера.

Уточнение: временно сохранённые фотографии представлены Telegram `file_id` в SQLite. Это служебные идентификаторы, они не показываются пользователю в чате.

## Публичные ссылки и фотографии карточек

В `.env` можно указать базовый адрес будущего лендинга:

```text
PUBLIC_BASE_URL=https://example.com
```

Если переменная не указана, используется безопасный тестовый адрес `https://example.com`. Для готовой карточки бот автоматически создаёт короткий случайный slug длиной 8 символов и показывает ссылку вида:

```text
https://example.com/p/aB7xK2mQ
```

У черновиков slug не создаётся. При повторном открытии готовой карточки её slug сохраняется, поэтому редактирование фото не меняет уже выданную ссылку.

В разделе `Мои объявления` Creator открывает карточку и видит фотографию товара **в той же media-панели**, что и форматированные данные, ссылка и inline-кнопки. Отдельное сообщение с фотографией не создаётся. Доступны действия `Открыть ссылку`, `Скопировать ссылку`, `Заменить фото` и `Удалить фото`. Фото хранится как Telegram `file_id`; сам файл не копируется в SQLite, а служебный идентификатор не показывается в обычном чате.

На экранах предпросмотра и готовой карточки общий баннер проекта заменяется фотографией товара. В главном меню, профилях, настройках, информации и других общих разделах остаётся общий баннер проекта. Если фото нет, карточка возвращается к баннеру и показывает пометку `Фото: не добавлено`.

Пока backend и динамический лендинг не опубликованы, ссылка отображается и создаётся в боте как подготовленный URL, но её содержимое ещё не будет получать данные из локальной SQLite-базы. Полная работа ссылки начнётся после подключения публичного backend к Vercel-лендингу.

## Публичный Flask API для лендинга

Приложение теперь запускает Telegram polling и Flask API в одном Python-процессе и на одном порту. Проверки доступны по `/` и `/health`. Публичная карточка запрашивается по адресу `/api/public/listings/<slug>` и отдаётся только если её статус `ready`. Черновики и отсутствующие slug возвращают 404.

Для карточки `aB7xK2mQ` локальный запрос выглядит так:

```text
http://127.0.0.1:10000/api/public/listings/aB7xK2mQ
```

JSON содержит только публичные данные Custom Service и объявления: название, тему, ссылки на логотип/favicon/фото, цену, валюту, условия отправки и контакт поддержки. Telegram-токен, Telegram ID Creator и внутренние данные базы в JSON не попадают.

Изображения отдаются серверными маршрутами:

```text
/api/public/listings/<slug>/media/listing
/api/public/listings/<slug>/media/logo
/api/public/listings/<slug>/media/favicon
```

Пока бот работает только локально, Vercel не может обратиться к `127.0.0.1`. Для публичной работы API потребуется разместить приложение на Render/VPS и направить отдельный API-поддомен, например `api.safe-swiss.online`, на этот сервис. После этого Vercel-лендинг сможет запрашивать конфигурацию карточки по slug.
